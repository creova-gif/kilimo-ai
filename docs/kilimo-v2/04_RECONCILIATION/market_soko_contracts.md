## Summary

- **Matrix rows: 62** (35 Figma frames + 27 Git-only / added items). Decisions: **KEEP FIGMA 8 · KEEP GIT 6 · MERGE 10 · REDESIGN 10 · REMOVE 23 · ADD 5** (counts computed from the table by script).
- **One paradigm: Soko.** The `Mobile / Soko /*` family is the only one that draws a real workflow (search → detail → offer → counter → order → track → fulfil → history, with the same Ununuzi/Mauzo view for both sides). The `Mobile / Market /*` family is kept only for Contracts (redesigned, deferred) and Input Supply (deferred); its Trends, Supply Chain, Buyer/Input-Supplier dashboards, Browse v2 and the superseded v1 are removed. Two seller dashboards collapse to one (`57:834`).
- **Only the first three workflow stages have a backend.** `market_listings` (browse / create / update-own, RLS, realtime) is *exists+tested*. Offers, orders, payments, price alerts, ratings, contracts, input-supplier catalogue/orders have **no table, function or API** (capability matrix; `grep` of `supabase/migrations` finds no `contracts`, `offers`/`orders` tables and no storage bucket).
- **The Git "workflow" is simulation.** Make Offer only fires a local notification claiming "sent to the seller" (`market.tsx:2101-2116`); checkout invents an order marked "On the Way" plus an "Order Placed!" alert (`:578-597`); price alerts keep local state yet promise "you will be notified" (`:1474-1481`); contract "Sign Digitally" auto-counter-signs *as the buyer* 800 ms later (`contracts/[id].tsx:233-237`); "Mark Paid" flips a local flag (`:542`).
- **The Market screen still renders fabricated content** (the #74 "fake market predictions" fix landed in analytics, not here): `MARKET_DATA` prices/trends/"AI Outlook" (`market.tsx:71-219,1203`), `STORE_PRODUCTS` + `STORE_REVIEWS` with real company names, ratings, stock, named reviewers (`:275-395`), `SEED_LISTINGS` shown as initial state and after any fetch failure (`useMarketIntelligence.ts:34-99,108`), five seeded DB rows incl. `escrow_funded = true` (migration `20260805000000:40-47`), three seeded contracts with company names (`useContractsStore.ts:110-176`), seeded "VERIFIED" suppliers (`useFarmDataStore.ts:273-337`). Figma carries its own (Trends "Bei ya Mahindi inatarajiwa kupanda kwa 15%", browse hint "820 – 880", escrow "IMELINDWA", supply-chain 24.5 °C / "A+").
- **A buyer cannot reach a seller.** Live listing cards are not tappable (`market.tsx:964-1067`), the search box never filters them, and "Make Offer" targets a benchmark price card, not a listing. Phase 1 therefore = discover + listing detail + contact seller (opt-in phone call/SMS/WhatsApp) — the honest low-connectivity path that needs no new payment/offer backend.
- **Phases:** P1 Soko discovery + listings + contact (backend exists; add listing columns/photos) · P2 offers → orders → status tracking (needs `offers`, `orders`, `order_events`, server-side notification creation) · P3 in-app payment, contracts, input supply, ratings (needs payment provider + legal + supplier partners).
- **Contracts:** store models 9 statuses with a free-text buyer; `docs/backend/contracts.md` plans 6 statuses with user-id parties. They disagree; reconcile on the backend plan before any UI is rebuilt. Hide `/contracts` from the launch build meanwhile.
- **Sibling docs:** Soko already a visible tab (matches `dashboard_farm_weather_map.md` #4); "prices only from `market_listings` with date + marker" (its §Fabricated) is implemented here as the ADD row "Bei kwenye matangazo"; `offline manager` KEEP GIT (`auth_onboarding…md`) confirmed for the listing queue with one rename (`market_order` → `market_listing`).

## Final marketplace information architecture

**One paradigm, one tab: Soko.** Everything a farmer does in the market is reached from `Soko` (tab 4) with two entry contexts and one activity hub. No separate "Market" and "Soko" trees.

```
Soko (tab root: Discover)                 [P1]
 ├─ header: region pill · search · [Shughuli Zangu]
 ├─ chips: Yote · <crop chips> · Karibu Nami        (Pembejeo chip hidden until P3)
 ├─ listing list → Listing detail                    [P1]
 │     ├─ Contact seller: Piga simu · SMS · WhatsApp [P1]
 │     ├─ Toa Bei (offer)                            [P2]
 │     └─ Seller profile (minimal)                   [P2]
 ├─ price summary card "Bei kwenye matangazo"        [P1, only if ≥ N listings]
 └─ FAB "Weka Tangazo" → Create listing              [P1]

Shughuli Zangu (one hub; segmented, role-agnostic)
 ├─ Matangazo Yangu  — my listings, edit / mark sold   [P1]   (was Seller Dashboard)
 ├─ Mapendekezo      — offers sent / received          [P2]   (My Offers + Seller Offers)
 ├─ Maagizo          — Ununuzi / Mauzo, tracking       [P2]   (Order Tracking/Fulfilment/History/Management)
 └─ Mikataba         — contracts                       [P3]
```

- **Modes, not separate apps.** Every signed-in role except `extension_officer` (`marketplace: 'none'`, `lib/access.tsx`) can buy and sell; role only changes the *default segment* (farmer → Matangazo Yangu if they already have listings, otherwise Discover; buyer → Discover; input supplier → Discover with a "Pembejeo zinakuja" note until P3). Roles are client-selected and unverified, so this is routing, not authorization; RLS is the boundary.
- **Input suppliers** appear later as sellers of a second listing `kind` (`input`) in the same feed with a separate chip — not as a parallel store/cart/dashboard. Their dashboard (`108:1382`) is a P3+ inventory product.
- **Contracts fit as the terminal of a negotiation, not a side menu:** an accepted offer can be "geuzwa kuwa mkataba" (forward contract with stage + payment milestones) in P3. Until the backend exists the route is hidden (remove `contract_farming` from `features.tsx` group at `:417` and any Soko link), not shown with seeded data.
- **Buyer dashboard and Trends are not screens.** What they contained is either derived from listings (price summary card) or removed (predictions, KPIs).
- **Input supply is not in the Soko tab in P1**; `app/input-supply.tsx` stays unreachable.
- **Tab title/icon:** "Soko" (Swahili) in both languages' primary label with EN accessibility label "Market"; not "Pembejeo Marketplace".
